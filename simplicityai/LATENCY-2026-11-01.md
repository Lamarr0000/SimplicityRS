# Host latency and interruption follow-up — 0.6.1

The user verified prompt speech interruption, but reported roughly 10 seconds to
transcribe, 20–30 seconds to display a reply and another 5–10 seconds for speech.
Server logs measured recent transcription at 2.8–4.7 seconds, model calls at
7.6–18.1 seconds and speech sections at 1.5–9.2 seconds. Those server stages do not
include all browser endpointing, queueing, display and playback time.

Ollama reported gpt-oss:20b allocated about 14.05 GB, with 6.07 GB in VRAM and
context 8192. CPU/memory work is a likely contributor; this does not isolate every
delay. The application still uses gpt-oss:20b.

## Changes

Playback interruption previously requested cooperative model cancellation while
the HTTP reader could remain blocked. A bounded network reader queue now keeps
blocking socket I/O off the agent thread. Cancellation wakes the agent promptly,
shuts down only that request's connection and discards its queued output. The
network reader owns file cleanup so Windows buffered reads cannot deadlock a
cross-thread close on the agent thread. Existing in-flight desktop operations
remain cooperative: they may finish; subsequent actions are prevented.

Loopback tests cover stalled HTTP/1.0 and HTTP/1.1 responses, pre-cancelled
requests and complete normal streams. The cancellation scenarios passed repeated
runs. A real local Ollama check requested cancellation at 0.800 seconds and
returned at 0.814 seconds. A subsequent “Say ready” request completed in 4.65
seconds. This is a controlled transport check, not an end-to-end voice result.

The VM TLS relay can briefly retain its upstream slot after client cancellation;
an immediate follow-up in the relay test returned HTTP 429. Relay-side prompt
cancellation/backpressure still needs investigation before a VM release. Do not
claim the real relay follow-up test passed. Host development continues first.

Spoken turns request one or two short sentences, usually under 40 words, while
retaining qualifications and allowing requested detail. The first speech section
is bounded at 120 characters; later sections remain bounded at 240. No tool or
diagnostic boundaries were relaxed. A new timing endpoint logs only whitelisted
stage names and bounded durations: transcription roundtrip, model queue wait,
text reply wait and first audio wait. This should separate perceived transcription
delay from waiting on an earlier model turn. No audio is saved by those metrics.
Expected client disconnects no longer produce a response-write traceback.

## Smaller-model comparison

Installed Granite 4 3B solely for a synthetic comparison, using the official
Ollama package: https://ollama.com/library/granite4:3b (Q4_K_M, about 2.1 GB).
No tools were executed by the benchmark. The cold greeting took 35.84 seconds;
cached subsequent cases took 1.21–2.29 seconds. It selected valid Calculator and
confirmed-target network calls, but also requested diagnostics with an unknown
target and an unnecessary target confirmation for an outside-host request.
Runtime guards would reject unauthorized diagnostics, but the model did not pass
the behavioral gate, so it was not promoted. Baseline gpt-oss was restored/warmed.
Do not treat six synthetic cases as a comprehensive quality evaluation.

The comparison runner is prototype/benchmark_latency.py. Detailed synthetic output
and cancellation measurements are retained in host logs outside Git. No prompts
from the user's live conversation are embedded in the benchmark source.
